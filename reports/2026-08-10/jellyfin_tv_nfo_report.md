## NFO 的写法

每个正片旁只写最小信息，例如：

```xml
<?xml version="1.0" encoding="utf-8"?>
<episodedetails>
  <season>3</season>
  <episode>1</episode>
</episodedetails>
```

不把标题、简介、演员、海报等写死在 NFO 中；这些继续交给 Jellyfin 的互联网元数据/图片获取器补齐。

## 2026 年 7 月新番：未来集数

未来文件的**完整文件名现在并不存在**，所以不能提前放一个能被 Jellyfin 命中的同名 NFO；Jellyfin 的 episode NFO 必须和视频同名。

因此脚本采用更稳妥的方式：对以下仍在更新、且当前命名规律稳定的作品使用开放匹配规则。新一集下载到原目录后，再运行一次同一个脚本，它会自动读出新文件名里的集数并生成对应 NFO：

- 100女友 第3期
- 世界在起舞
- 地狱模式 2nd Season
- 幼女战记Ⅱ
- 描绘直至生命尽头
- 攻壳机动队 THE GHOST IN THE SHELL
- 无职转生 第3期

其中 `100女友 第3期` 使用总话数换算：`25 → S03E01`，之后 `26 → S03E02`、`27 → S03E03`……；脚本对后续 30、31……同样有效。

## 使用方法

1. 在仓库根目录运行 `scripts/jellyfin_tv_nfo_fix.ps1`；脚本默认读取 `rules/jellyfin_tv_nfo_rules.json`。
2. 先只预演：

```powershell
.\scripts\jellyfin_tv_nfo_fix.ps1
```

3. 检查输出与 `jellyfin_tv_nfo_run_log.csv`；确认后实际写入：

```powershell
.\scripts\jellyfin_tv_nfo_fix.ps1 -Apply
```

4. 默认**绝不覆盖已有 NFO**。只有你明确希望覆盖时才使用：

```powershell
.\scripts\jellyfin_tv_nfo_fix.ps1 -Apply -OverwriteExisting
```

5. 写完后，在 Jellyfin 中对受影响作品执行媒体库扫描/刷新元数据。

## 公开仓库中的数据范围

原始 `anime-library.csv`、`jellyfin-library-export.json` 和按真实文件名生成的 NFO 压缩包不提交到公开仓库：它们会暴露完整本地媒体库存或大量具体文件名。公开仓库保留可复现修复所需的脚本、34 条规则、修正汇总和 NFO 示例；实际 NFO 可在本地由脚本重新生成。

## 详细清单

- `jellyfin_tv_nfo_corrections.csv`：按规则汇总当前匹配数量、目标 Season/Episode 范围和未来规则。
- `jellyfin_tv_nfo_unresolved_specials.csv`：不自动处理的 SP/Extras 分类汇总。
- `jellyfin_tv_not_in_library.csv`：未进入 Jellyfin 的目录汇总。
- `rules/jellyfin_tv_nfo_rules.json`：脚本使用的全部 34 条命名规则。
